Проблема: AI туповат, «вытягивает клещами» информацию, заводит чат в дебри.

Примеры:
- Пользователь говорит «банкротство надо юрист нужен» → AI спрашивает сумму долга
- Пользователь говорит «давайте консультацию» → AI снова спрашивает сумму долга
- Пользователь не понимает вопросы → AI повторяет их формально
- Хуже, чем показанный «эталонный чат»

КОРЕННЫЕ ПРИЧИНЫ:
1. **DialogStrategy тупой FSM** — неумная логика этапов
2. **Системный промпт не реализуется** — правила в SYSTEM_INSTRUCTION остаются на бумаге
3. **ProfileMemory плохо извлекает** — не видит 310к, город
4. **IntentDetector слишком простой** — не распознаёт намерения типа «хочу консультацию»
5. **Context недостаточен** — RAG не находит важную информацию (порог 500к, стоимость консультации)
6. **Чат не сохраняет состояния** — FSM сбрасывается при каждом запросе

ЦЕЛИ:
- AI должен вести диалог как внимательный менеджер:
  - Слышит, что клиент уже сказал «хочу консультацию» → предлагает собрать данные
  - Не повторяет уже заданные вопросы
  - Объясняет причины (почему нужна сумма долга)
  - Даёт четкий следующий шаг
- Ответы должны быть красивыми, естественными, логичными
- Контекст RAG должен правильно использоваться

### Шаг 1 — ДИАГНОСТИКА

✅ Проверяем текущую систему:
- DialogStrategy — стадия WELCOME → QUALIFY → CONSULTATION_READY → HANDOFF
- Условия перехода: не хватает суммы долга → всегда спрашиваем сумму
- Системный промпт — 6 разделов, но AI не следует им
- ProfileMemory не находит сумму из «рассрочку на 310к платить уже не могу»
- IntentDetector: только привет/спасибо/прощание/вопрос

🔍 НАЙДЕНЫ ПРОБЛЕМЫ (проверено по коду и по КЦ.docx):
A. СОСТОЯНИЕ ЧАТА (не RAG):
1. ChatService.ask() создаёт ProfileMemory() и DialogStrategy() ЗАНОВО на каждый
   запрос → FSM всегда стартует с WELCOME → hint вечно «собрать информацию»,
   stage никогда не доходит до CONSULTATION_READY (шаг 13 цепочки chat.md — мёртв)
2. ProfileMemory.extract() смотрит и на реплики АССИСТЕНТА (combined = история + вопрос)
   → цифры из ответов бота попадают в профиль клиента; берётся ПЕРВОЕ совпадение
3. IntentDetector — только точное совпадение привет/спасибо/пока;
   «банкротство надо», «давайте консультацию», «давай стоимость» → QUESTION, без маршрута
4. QueryCondenser склеивает последние 3 реплики ВКЛЮЧАЯ длинные ответы ассистента
   в один «standalone-запрос» → эмбеддинг размывается, в топ-k falls случайное

B. ГЛУШИВЛЕНИЕ (RAG + гейт):
5. SCORE_THRESHOLD=0.02 (.env) → passes_threshold() истинна почти всегда →
   Grounding.NOT_ANSWERABLE недостижим, «Не знаю» невозможна → LLM отвечает
   на всё, даже когда релевантного контекста нет
6. ⚠️ ФАКТ: в КЦ.docx НЕТ порога «500 000 ₽». Ответ чата про 500к — галлюцинация
   модели. В документе внутренний критерий компании: «берем в процедуру только
   с суммой от 350к» + регион прописки (не работаем: Чечня, ДНР, ЛНР, Владимирская обл.)
7. КЦ.docx — это скрипт продаж (60 абзацев, 18К знаков), а НЕ юридическая справка:
   в нём нет сумм/сроков/порогов закона → любые юридические цифры в ответе = выдумка
8. Регион прописки — ключевой критерий квалификации, чат его НИКОГДА не спрашивает
